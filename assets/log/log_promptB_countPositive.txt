  What the tests check:
  - Counting: empty arrays, all-positive, all-negative and mixed arrays,
    repeated values, decimals, Infinity and -Infinity, and a 1000-element array.
  - Zero is not positive: 0, -0 and NaN aren't counted. This is the boundary
    that most often catches a >= bug.
  - Return value: the result is a number, and the input array is left unchanged.
  - TypeError: thrown for undefined, null, a number, a string, a boolean, a
    plain object, an array-like object, a function, and when called with no
    arguments.

  Assumptions you may want to change:
  - Positive means > 0. The spec doesn't define it, so I went with that.
  - Number elements only. The spec types elements as Object[] but doesn't say
    what happens with strings like '5' or other non-numbers, so I left those out
    rather than guess.
  - Typed arrays aren't tested. Int8Array and similar aren't real arrays in
    JavaScript, but whether they should throw is unclear, so I skipped them.
  - The input-unchanged test isn't in the spec. It's a reasonable expectation
    for a counting function, but you can remove it if you want to test only what
    the spec says.

  The tests load countPositive from ./countPositive.js and expect it to be
  exported as module.exports = { countPositive }. Once that file exists, run
  them with:

  node --test countPositive.test.js
