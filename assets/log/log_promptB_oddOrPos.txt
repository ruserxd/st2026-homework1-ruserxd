⏺ I wrote 28 tests in oddOrPos.test.js. Run them with node --test.

  What the tests check:
  - Counting: an empty array gives 0, and the function returns a number.
  - Positive numbers: odd, even and fractional positives are all counted,
    because being positive is enough.
  - Negative numbers: negative odd numbers are counted, because being odd is
    enough. Negative even numbers and negative fractions are not counted.
  - Zero: 0, several zeros and -0 are not counted, since zero is neither odd nor
    positive.
  - Mixed arrays: each element is counted once even if it is both odd and
    positive, duplicates are counted separately, and very large values and long
    arrays work.
  - Input: the array passed in is not changed.
  - TypeError: it's thrown when called with no argument, undefined, null, a
    number, a string, a boolean, a plain object, an object that looks like an
    array ({length: 2, ...}), a Set or a function.

  Testing the tests: there's no implementation of oddOrPos in the folder yet, so
  I tried the tests against two throwaway versions in a temporary folder, not
  in your project.
  - A correct version passed all 28.
  - A version with a common bug, v % 2 === 1, failed 6. In JavaScript -3 % 2 is
    -1, so that check misses negative odd numbers. The negative-odd cases are
    there to catch this.

  Assumptions to adjust if needed:

    oddOrPos } from ./oddOrPos.js. Change the require line if you export it
    another way.
  - The spec says Object[] but doesn't say what happens with non-number elements
    like "3", null or NaN. I didn't test those, since any expected result would
    be a guess.
