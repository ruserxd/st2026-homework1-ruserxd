  What the tests cover:
  - Finding the last index: the value appears several times, once, first, last,
    or in every position; one-element arrays; zero, negative and decimal
    numbers; ±Infinity; a 100,000-element array; and a check that the input
    array isn't changed.
  - Returning -1: an empty array, no match, a one-element array with no match,
    and an array with no numbers in it.
  - TypeError when x isn't an array: undefined, null, a number, a string, a
    boolean, an object that looks like an array, and a function.
  - TypeError when y isn't a number: undefined, null, '1', a boolean, {}, [1],
    and 1n. One test uses an array containing '1' to check that the function
    rejects '1' rather than matching it, and another uses an empty array.
    Missing arguments and both arguments invalid also throw.

  Cases the spec doesn't decide, which I tested only loosely or left out:
  - NaN: it counts as a number, so the tests only check that it doesn't throw.
    The spec doesn't say whether findLast([NaN], NaN) should return 0 or -1.
  - How values are compared: the spec doesn't say whether findLast(['2', 2, 
    '2'], 2) should match the string '2' (giving 2) or not (giving 1), or
    whether 0 should match -0.
  - Unusual inputs: typed arrays like Int8Array, number objects like new 
    Number(1), and arrays with gaps aren't clearly in or out of the spec.
